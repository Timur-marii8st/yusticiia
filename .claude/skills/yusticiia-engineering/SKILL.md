# Работа с кодом «Второго мнения»

## Что это за проект и чем он отличается

Система юридического аудита проекта судебного акта. Отличие от обычного
веб-приложения одно, но оно определяет всё: **каждое утверждение должно
раскрываться до цитаты, нормы, редакции и источника**. Отсюда правила,
которые в другом проекте выглядели бы избыточными, а здесь обязательны.

Требования пронумерованы в `docs/TZ.md`. Задача без требования не
берётся: сначала требование, потом код — иначе через месяц спор пойдёт
по второму кругу.

## Порядок перед любым коммитом

```bash
ruff check .        # линтер
mypy                # типы, 70+ модулей, должно быть чисто
pytest --cov        # тесты и порог покрытия 80%
second-opinion norms-seal --check   # если трогали корпус норм
python -m evaluation.run            # если трогали извлечение/поиск/правила
```

Базу для 16 тестов PostgreSQL/pgvector поднимать так:

```bash
docker run -d --name so-test-pg -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=second_opinion_test \
  -p 55432:5432 pgvector/pgvector:pg16
SO_TEST_DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:55432/second_opinion_test pytest --cov
```

Без переменной эти тесты **молча уходят в skip**, и прогон выглядит
зелёным, ничего не проверив. Docker Desktop на этой машине периодически
гаснет сам — проверяйте `docker info`, а не надейтесь.

После работы обновить: `docs/TZ.md` (статус требования) и
`CHANGELOG.md`. Это не бюрократия: один раз документация уже отстала от
кода на тринадцать итераций. Полные инженерные правила —
`references/engineering-rules.md`, открытые вопросы —
`references/open-questions.md`.

## Инварианты, которые не обсуждаются

Полный список — раздел 5 `docs/TZ.md`. Три, которые ломают чаще всего:

**Цитата обязана дословно находиться в документе.** Любое изменение
текста, который видит извлекатель, ломает сопоставление цитат. Если текст
всё же нужно изменить (например, обезличить перед передачей модели) —
замена обязана сохранять длину, иначе оффсеты поедут и факты отсеются как
выдуманные.

**Норма применяется в редакции на юридически значимую дату**, а не в
текущей. Свежая редакция не подставляется молча — ни в коде, ни в
плановой автоматике.

**Статистика не является основанием для наказания.** Формулировки
проверяются тестом: слова «следует», «рекомендуется», «завышен»,
«занижен» в описательных выводах недопустимы.

## Ловушки этого проекта

Каждая стоила времени здесь, а не взята из общих соображений. Подробный
разбор с симптомами — `references/pitfalls.md`. Коротко:

| Симптом | Причина |
|---|---|
| «Кнопка не работает», в коде всё верно | не поднята метка `?v=` у `app.js`/`style.css` в `index.html` — браузер отдаёт старый файл |
| Правка не видна в браузере | сервер не перечитывает код: нужен перезапуск `second-opinion serve` |
| Тест не видит `monkeypatch.setenv` | `load_config` под `lru_cache`, нужен `load_config.cache_clear()` |
| Падает `test_api_docs_match_routes` | новый эндпойнт не описан в `docs/API.md` |
| Падает `test_openapi_schemas` | ответ не JSON (файл) и не описан явно в `responses` |
| mypy ругается на обработчик FastAPI | это идиома «объявили модель, вернули dict»; переопределение уже настроено в `pyproject.toml`, не переписывайте обработчики |
| Прогон зелёный, но ничего не проверил | не задан `SO_TEST_DATABASE_URL` |
| У всех обстоятельств один значок «?» | `badge()` знала только статусы правил; статусы обстоятельств — другой словарь и уходили в запасной вариант |
| В интерфейсе видно `draft`, `PASS`, `pattern` | значение перечисления подставлено в текст напрямую, минуя таблицу подписей |
| Тесты зелёные, а `serve` не стартует | новый модуль записан поверх существующего; точка входа `make_app` в тестах не участвует |

## Карта проекта

```
src/second_opinion/
  domain/          модели: факты, нормы, отчёт, проблемные места
  ingestion/       парсеры TXT/MD/DOCX/PDF + OCR-фолбэк
  fact_extraction/ паттерны и модель за интерфейсом
  fact_values.py   проверка значения обстоятельства, введённого человеком
  rule_engine/     8 детерминированных правил; rules/ разложены по
                   предмету: sanction, stage, procedure, mitigating,
                   sentence, base
  legal_sources/   корпус норм, редакции, ИПС/ГАРАНТ, опечатывание
  legal_rag/       поиск по источникам с цитированием
  retrieval/       сопоставимые дела
  analytics/       описательная статистика, положение срока
  pipeline.py      конвейер: документ → факты → проверки → практика → отчёт
  reporting.py     изложение дела и проблемные места
  privacy.py       обнаружение и маскирование ПДн
  export/          заключение в .docx
  api/             app.py (сборка), routers/ по ресурсам, auth_mode,
                   errors, request_context, uploads, schemas, deps
  cli/             разбор аргументов + команды: serve, documents,
                   norms, redactions, bind
  storage/         файловый и PostgreSQL носители за протоколом
```

Файл называется по предмету, а не по слою. Модуль за 700 строк — повод
разложить его: так уже сделано с `rule_engine/rules.py`, `api/routes.py`
и `cli.py`. Публичные имена при этом сохраняются re-export'ом, чтобы
перестановка не расходилась с настоящим рефакторингом.

Документация в репозитории — для читателя системы: `docs/TZ.md`
(требования и статусы), `ARCHITECTURE.md`, `API.md`, `DATA_SOURCES.md`,
`NORM_COVERAGE.md`, `SECURITY.md`, `PRIVACY.md`,
`LEGAL_SAFETY_PRINCIPLES.md`, ADR в `docs/ADR/`.

Рабочие материалы разработки — здесь, в `references/`: инженерные
правила, открытые вопросы, архив статусов и дорожной карты.

Про источники текстов законодательства — отдельный скилл
`legal-data-sources`: что даёт ИПС, почему отклонены RusLawOD и
Russian-Law-MCP, чего ждать от ГАРАНТ.

  до того, как её увидит человек

- `references/history/` — архив: помесячные статусы реализации и
