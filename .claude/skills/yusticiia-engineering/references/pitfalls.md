# Ловушки: симптом, причина, что делать

Каждая запись — случай из этого проекта, а не общее соображение. Формат
одинаковый: как это выглядит снаружи, почему так, и как не попасть снова.

## 1. «Кнопка не работает», хотя код верный

**Симптом.** Правка в `app.js` внесена, сервер перезапущен, в браузере
ничего не изменилось. Обработчик не срабатывает, ошибок в консоли нет.

**Причина.** `index.html` ссылается на статику с меткой версии:
`app.js?v=0.49`. Браузер кэширует файл по этому URL. Пока метка та же,
он отдаёт старый файл — включая тот, где нужного обработчика ещё нет.

**Что делать.** Поднимать метку у **обоих** файлов при любой правке
`app.js` или `style.css`. Проверять так: открыть страницу с новым
параметром (`http://127.0.0.1:8000/?x=1`) — это сбивает кэш HTML, но
не кэш статики, поэтому метка всё равно нужна.

**Цена ошибки в этом проекте:** дважды выглядело как «функция не
реализована», хотя она была написана и работала.

## 2. Сервер не перечитывает код

**Симптом.** Новый эндпойнт отвечает 404, новое поле отсутствует в
ответе, хотя тесты на него зелёные.

**Причина.** `second-opinion serve` запущен без перезагрузки; процесс
держит старый код в памяти.

**Что делать.** После правки серверного кода — перезапуск:

```bash
pkill -f 'second-opinion serve'
SO_DATA_DIR=... nohup second-opinion serve --host 127.0.0.1 --port 8000 &
```

Сначала подумать, не в этом ли дело, и только потом искать ошибку в коде.

## 3. Тест не видит переменную окружения

**Симптом.** `monkeypatch.setenv("SO_AUTH_MODE", "accounts")` выставлен,
а приложение ведёт себя так, будто переменной нет. Тест проверяет не то,
что думает, и может «проходить» на неверном поведении.

**Причина.** `load_config` помечен `@lru_cache`. Первое чтение конфигурации
случается раньше, чем тест меняет окружение, и дальше отдаётся кэш.

**Что делать.** После `setenv` звать `load_config.cache_clear()` и
сбрасывать кэш в конце теста. Образец — фикстура `auth_mode` в
`tests/integration/test_auth_modes.py`.

## 4. Свои же тесты ловят незадокументированный эндпойнт

**Симптом.** `test_api_docs_match_routes` падает после добавления
маршрута.

**Причина.** В проекте есть тест, сверяющий фактические маршруты со
справочником `docs/API.md`. Эндпойнт, которого нет в справочнике, — это
ошибка, а не мелочь: API описывает контракт для судебной системы.

**Что делать.** Добавлять строку в `docs/API.md` в том же коммите. Это
занимает минуту и снимает целый класс расхождений.

## 5. Бинарный ответ ломает схему OpenAPI

**Симптом.** `test_openapi_schemas` сообщает «ответ описан как любой
объект».

**Причина.** Обработчик отдаёт файл (`.docx`), а не модель. Без явного
описания FastAPI объявляет ответ произвольным объектом, и по
спецификации невозможно понять, что эндпойнт отдаёт документ.

**Что делать.** Описывать ответ явно:

```python
@app.get(
    "/api/analyses/{analysis_id}/document",
    response_class=FileLikeResponse,
    responses={200: {"content": {DOCX_MEDIA_TYPE: {"schema": {"type": "string", "format": "binary"}}}}},
)
```

## 6. mypy ругается на каждый обработчик FastAPI

**Симптом.** Три десятка ошибок вида «Incompatible return value type (got
dict, expected SomeResponse)».

**Причина.** Обработчики объявляют модель ответа и возвращают словарь —
фреймворк валидирует его той же моделью. Формально несовпадение, по
существу идиома.

**Что делать.** Ничего: в `pyproject.toml` для `second_opinion.api.*`
отключены коды `return-value` и `misc` с объяснением. **Не переписывать**
обработчики ради формальности: это риск поведения там, где ошибку и так
ловят валидация ответа и `test_openapi_schemas`.

## 7. Зелёный прогон, который ничего не проверил

**Симптом.** `pytest` зелёный, но в конце «16 skipped».

**Причина.** Тесты PostgreSQL/pgvector пропускаются без
`SO_TEST_DATABASE_URL`. Ровно так слой хранения не проверялся ни разу за
всё время своего существования, пока это не обнаружили.

**Что делать.** Поднимать базу (команда — в `SKILL.md`) и смотреть на
число пропущенных, а не только на слово «passed».

## 8. Ротация журнала, теряющая записи

**Симптом.** После ротации в файлах меньше записей, чем было записано.

**Причина.** Имя ротированного файла содержало отметку времени с
точностью до секунды. Две ротации в одну секунду давали одно имя, и
`os.replace` затирал предыдущий файл.

**Что делать.** При совпадении имени добавлять порядковый номер. И
помнить, что для аудит-журнала «потеряли немного» — это не мелочь: журнал
ведётся ради провенанса.

## 9. Маскирование, ломающее цитаты

**Симптом.** После включения обезличивания модель перестаёт давать факты:
все отсеиваются как «цитата не найдена в документе».

**Причина.** Цитата ищется в тексте по совпадению. Если замена меняет
длину фрагмента, оффсеты сдвигаются, и вернувшаяся цитата не находится.

**Что делать.** Для текста, который уходит модели, использовать
маскирование с сохранением длины (`MaskStyle.PRESERVE_LENGTH`), искать
цитату в замаскированном тексте, а показывать — по оригиналу тех же
оффсетов. Читаемое маскирование (`READABLE`) годится только там, где
текст больше не сопоставляется — например, в файле заключения.

## 10. Тест, который невозможно выполнить через HTTP-клиент

**Симптом.** Тест на «опасное значение заголовка» падает внутри httpx с
ошибкой кодирования, не дойдя до проверки.

**Причина.** Клиент отказывается отправлять заголовок с кириллицей или
переводом строки раньше, чем запрос уйдёт.

**Что делать.** Проверять такие случаи на уровне функции, а не запроса, и
объяснять в тесте, почему так. Защита в коде всё равно нужна: значение
попадает в журнал, а туда оно может прийти не только из браузера.

## 11. Артефакты прогона в коммите

**Симптом.** В коммите появился `.coverage` — бинарный файл данных.

**Причина.** Новый инструмент создаёт файл в корне, а `git add -A` берёт
всё подряд.

**Что делать.** Добавлять правило в `.gitignore` в том же коммите, где
появляется инструмент. Смотреть на список файлов в выводе `git commit`, а
не только на его код возврата.

## 12. Фикстуры моделей требуют полей, о которых забываешь

**Симптом.** `ValidationError: court Field required, date Field required`
при сборке `ComparableCase` в тесте.

**Причина.** Модель дела требует суд и дату — у синтетических фикстур они
есть, а в наскоро собранном тестовом объекте забываются.

**Что делать.** Собирать тестовые объекты маленькой функцией-помощником в
самом файле теста, а не копировать поля по одному.

## 13. Путь из идентификатора

**Симптом.** Не воспроизводится через HTTP — и потому легко счесть
несуществующим.

**Причина.** Файловый репозиторий строил путь как `каталог/<id>.json`.
`get("../secret")` читал, а `delete("../secret")` удалял файл рядом с
хранилищем. Маршрут FastAPI такой идентификатор не пропускает, но те же
методы зовут из CLI и из скриптов.

**Что делать.** Не рассчитывать на предупредительность вызывающего.
Идентификаторы проверяются шаблоном в `storage/repositories.py`;
отклонённая попытка пишется в лог, сохранение с негодным идентификатором
поднимает исключение — это ошибка своего кода, а не атака.
