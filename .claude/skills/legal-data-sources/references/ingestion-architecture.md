# Предложенная архитектура ingestion

Схема, к которой пришли при разборе источников. Она отвечает на вопрос
«откуда берётся и как обновляется текст нормы», а не «как устроен наш код»
(это в `implemented.md` и в документации репозитория).

## Чего делать не надо

```
каждый запрос судьи → pravo.gov → PDF → OCR → LLM
```

Распознавание в горячем пути — кошмар по скорости, стоимости и
надёжности, и при этом каждый раз заново.

## Конвейер

```
         RusLawOD (опционально, разовый импорт)
         304k документов
                │
                ↓
         ┌─────────────────┐
         │ Legal Database  │      наша база норм
         │ PostgreSQL      │      + поиск
         └────────┬────────┘
                  │
publication.pravo.gov.ru/api/Documents
                  │  новые публикации
                  ↓
         ┌──────────────────┐
         │ update detector  │      что изменилось
         └────────┬─────────┘
                  │
      pravo.gov.ru/proxy/ips/      HTML / plaintext
                  │
                  ↓
             normalizer
                  ↓
             versioning
                  ↓
   ┌────────────────────────┐
   │ law_id                 │
   │ article                │
   │ text                   │
   │ valid_from             │
   │ valid_to               │
   │ source_nd              │
   │ source_eo_number       │
   └────────────────────────┘

   и только если текста нигде нет:  PDF → OCR
```

Смысл схемы в одном: **OCR становится редким фолбэком, а не основным
ingestion**.

## Разделение ролей между источниками

| Роль | Источник |
|---|---|
| обнаружение новых актов | `publication.pravo.gov.ru/api/Documents` |
| читаемый текст нормы | ИПС `pravo.gov.ru/proxy/ips/` |
| официальный контрольный оригинал | PDF с publication |
| периоды действия редакций (когда появится токен) | ГАРАНТ `/v2/redactions/{id}` |
| разовый массив текстов для поиска | RusLawOD |

## Где конвейер обязан останавливаться

Машина доводит дело до **черновика** и зовёт человека. Черновик — это
редакция со статусом `draft`, пустыми `sanctions` и записанным
происхождением. Человек проставляет:

- границы действия редакции (источник даёт дату акта, а не дату
  вступления в силу);
- пределы санкции в месяцах (из текста они не выводятся);
- статус `verified` — юридическое утверждение, а не технический флаг.

После этого корпус опечатывается заново.

Это не осторожность ради осторожности: полностью автоматическое
обновление норм — прямое нарушение правила «never: silently apply the
latest law version to historical cases» из `docs/ENGINEERING_RULES.md`.

## Обнаружение устаревания

Отдельный от ingestion механизм, отвечающий на вопрос «не изменилось ли с
тех пор, как мы выгрузили». Работает на сравнении **координат редакции
источника**, записанных вместе с текстом (`источник:документ:редакция`),
с номером последней редакции у источника.

Ключевое свойство: норма без записанных координат попадает в «проверить не
удалось», а не в «актуальные». Отсутствие данных не превращается в
подтверждение — иначе непроверенное выглядело бы проверенным.

Реализация и команды — в `implemented.md`.
