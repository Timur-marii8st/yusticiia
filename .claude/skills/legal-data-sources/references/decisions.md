# Зафиксированные решения

Каждое решение — с основанием. Записаны, чтобы разбор не повторялся при
каждом упоминании темы: спор стоит вести о новых фактах, а не о старых.

## ИПС pravo.gov.ru — основной источник редакций

**Принято 14.09.2026** (ADR-009). Государственный, без токена и подписки,
отдаёт консолидированные редакции. Снимает лицензионный вопрос целиком.

Последствия: критический путь проекта больше не проходит через внешнюю
заявку; утверждение «норма не менялась» стало проверяемым одной командой.
Цена: дату вступления редакции в силу приходится сверять вручную, часть
редакций недоступна.

## Свой движок применения поправок не пишется

**Принято 14.09.2026 по факту проверки, а не из осторожности.** Источник
отдаёт готовые консолидированные тексты — собирать их из текстов поправок
не нужно. Альтернатива стоила бы месяцев работы при высоком риске ошибки
в праве.

Это был вопрос-гейт: пока не проверили, насколько хорошо из ИПС достаются
консолидированные редакции, писать свой движок было бы преждевременно.

## RusLawOD не используется

Корпус содержит исходные редакции без консолидированных, и авторы прямо
пишут, что источник не является официальным изданием. Для проверки
приговора 2024 года по редакции 1996 года негоден.

Вернуться стоит только под задачу полнотекстового поиска по массиву
законодательства — но не под редакции на дату.

## Russian-Law-MCP не рассматривается до появления истории редакций

Отклонён по собственному `COVERAGE_LIMITATIONS.md` проекта: только
текущий текст, судебная практика и постановления Пленума не включены.
Ранняя запись «репозиторий отдаёт 404» была ошибкой поиска и исправлена —
см. `sources/russian-law-mcp.md`.

## ГАРАНТ — второй провайдер за тем же интерфейсом

Клиент и заглушка написаны, включается сменой переменной окружения в день
получения токена. Из критического пути выведен.

Почему написали, не имея токена: развязка та же, что уже применена к LLM —
протокол, заглушка по умолчанию, реальный провайдер по конфигурации. Риск
в том, что имена полей могут не совпасть, поэтому слой преобразования
«ответ ГАРАНТ → наша модель» держится тонким и в одном месте.

Отклонённая альтернатива — «ждать токен, ничего не писать»: ноль риска
впустую написанного кода, но и ноль движения; при получении токена за
неделю до сдачи интеграции не будет.

## OCR — фолбэк, а не основной путь

Порядок: HTML-источник → текстовый слой PDF → локальный OCR → внешний
сервис (не нужен). Основание — в `sources/publication-pravo-gov.md`:
для норм узкое место не чтение файла, а юридическая сверка и
структурирование, и ошибка распознавания в числе меняет смысл нормы.

## Машинный вывод остаётся черновиком

Фикстура не выходит из `draft` без сверки юристом и опечатывания. Это
касается и текста из ИПС, и текста из PDF, и черновика, собранного
автоматикой по расписанию.

## Автоматика обнаруживает, но не обновляет

Плановая проверка сверяет корпус с источником и заводит задачу человеку.
Ни один автоматический шаг не пишет в корпус норм. Основание — правило
«never: silently apply the latest law version to historical cases» из
`docs/ENGINEERING_RULES.md`.

Следствие для реализации: недоступность источника и устаревание нормы
должны различаться по коду возврата, иначе упавший чужой сервер
превратится в сообщение «закон изменился», то есть в ложное утверждение.

## Предположение не выдаётся за наблюдение

Файлы заглушки ГАРАНТ обязаны объявлять `"assumed": true`, синтетические
дела — `synthetic: true`. Один и тот же принцип: данные, построенные по
документации или выдуманные для демонстрации, обязаны сами говорить об
этом, иначе однажды кто-то примет их за настоящие.
