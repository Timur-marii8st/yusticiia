# IMPLEMENTATION_PLAN

Разработка идёт малыми законченными итерациями. Каждый майлстоун завершается
работающим кодом, тестами и обновлением `IMPLEMENTATION_STATUS.md`.

## M0 — Foundation (текущий)

**Цель:** каркас проекта, документация, доменные модели, запуск одной командой.
**Результаты:** структура каталогов; `pyproject.toml`; ruff/pytest; доменные
модели (`domain/`); конфиг окружения; ADR-001…007; README; CI.
**Приёмка:** `pytest` зелёный на тестах моделей; `ruff check` чистый;
`python -m second_opinion.cli --help` работает.
**Тесты:** доменные инварианты (факт без evidence ≠ VERIFIED, temporal-запрос).

## M1 — Document ingestion

**Цель:** надёжный парсинг входных документов.
**Результаты:** парсеры TXT/MD/DOCX/PDF(текстовый слой) → `Document`
с оффсетами; репозиторий документов; защита от вредоносных файлов (лимиты
размера/типа).
**Приёмка:** все 4 формата проходят интеграционный тест; оффсеты точны.
**Тесты:** парсеры на фикстурах; краевые случаи (пустой файл, бинарный мусор,
очень большой файл).

## M2 — Legal facts

**Цель:** извлечение юридически значимых обстоятельств с доказательством.
**Результаты:** паттерновый экстрактор (квалификация, возраст, смягчающие,
наказание, процедура); LLM-экстрактор за `LLMProvider`; слияние результатов;
статусы фактов; `MockLLMProvider`.
**Приёмка:** на образце приговора извлекается ≥10 фактов, каждый `VERIFIED`
имеет цитату; невалидный LLM-JSON обрабатывается повтором/`UNKNOWN`.
**Тесты:** юнит на каждый паттерн; золотые тесты на образцах; тесты
деградированного LLM-вывода.

## M3 — Rule engine

**Цель:** детерминированные проверки Общей части УК.
**Результаты:** реестр правил; ≥3 правила (санкция статьи; ст. 66 покушение;
ст. 62 особый порядок/смягчающие; ст. 73 пределы условного); регрессионные
тесты на каждый сценарий.
**Приёмка:** 100% воспроизводимость; каждый `RuleEvaluation` несёт факты и
нормы с версиями.
**Тесты:** золотые кейсы на правило; статус `UNKNOWN` при неполных данных.

## M4 — Legal sources

**Цель:** хранилище норм с временны́ми редакциями.
**Результаты:** `NormStore` с `get_norm(norm_id, applicable_at)`; SHA-256;
загрузка из `data/fixtures/norms/`; маркировка `verification_status`.
**Приёмка:** выбор редакции по дате покрыт тестами, включая границу дат.
**Тесты:** временна́я корректность; контрольные суммы; отсутствие версии.

## M5 — Legal RAG

**Цель:** поиск норм и разъяснений с цитированием.
**Результаты:** лексический поиск по базе источников; метаданные-фильтры;
запрет ответа без фрагмента-источника. Позднее: эмбеддинги + реранкинг
(решение отложено, см. ADR-003).
**Приёмка:** на запрос «пределы наказания при покушении» возвращается
ст. 66 УК с текстом.
**Тесты:** Recall@K/MRR на подготовленных запросах.

## M6 — Comparable cases

**Цель:** поиск сопоставимых дел с объяснением отбора.
**Результаты:** загрузка фикстур дел (10–30, синтетические); структурные
фильтры; ранжирование; `reasons[]` у каждого результата.
**Приёмка:** фильтр «ст. 158 ч. 2 + особый порядок» возвращает только
подходящие дела с объяснениями.
**Тесты:** фильтры; отсутствие «процентного сходства» как основания вывода.

## M7 — Analytics

**Цель:** описательная статистика по выборке.
**Результаты:** N, медиана/среднее/перцентили, распределение видов наказания,
доля условного; только дескриптивные формулировки.
**Приёмка:** на фикстурах цифры совпадают с ручной проверкой.
**Тесты:** статистика на известных распределениях; пустая выборка → «нет данных».

## M8 — UI

**Цель:** интерфейс судьи (прогрессивное раскрытие).
**Результаты:** экран анализа: карточка дела → обстоятельства с цитатами →
проверки норм с раскрытием → практика → аналитика; редактирование фактов
человеком.
**Приёмка:** полный сценарий §28 задания выполняется в браузере без консоли.
**Тесты:** интеграционные через API + ручные сценарии по чек-листу.

## M9 — Evaluation

**Цель:** измеримое качество.
**Результаты:** `evaluation/` с датасетами и метриками:
P/R/F1 извлечения + evidence correctness/coverage; Recall@K, MRR, nDCG;
citation completeness; temporal correctness; регрессия правил;
`unsupported_claim_rate`. Команда `make eval`.
**Приёмка:** отчёт складывается в `evaluation/reports/` и читается человеком.
**Тесты:** метрики на контролируемых примерах.

## M10 — Hardening

**Цель:** подготовка к защите и эксплуатации.
**Результаты:** threat model и защита (prompt injection, malicious PDF,
утечка ключей, логирование PII); лимиты и ошибки; миграция на
PostgreSQL(+pgvector); Docker Compose; SECURITY.md/PRIVACY.md/DEPLOYMENT.md;
документация режимов внешнего LLM.
**Приёмка:** чек-лист угроз закрыт или явно принят как риск.
**Тесты:** инъекции в тексте документа не меняют поведение; аудит-журнал
не содержит сырых текстов.

## Правила процесса

- Майлстоун не закрыт, пока не работают его тесты и не обновлён статус.
- Порядок может уточняться, но M0→M3 идут строго последовательно: сначала
  проверяемое ядро, затем расширение.
