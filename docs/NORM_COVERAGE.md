# Редакционное покрытие норм

Отчёт: `second-opinion norms-coverage` (с `--strict` — ненулевой код выхода).

## Зачем

Система обещает «норму в редакции, действовавшей на юридически значимую
дату». Обещание держится ровно настолько, насколько полна редакционная
история в `data/fixtures/norms/`.

Из данных не видно разницы между двумя разными утверждениями:

- «статья с 1996 года действительно не менялась» — проверенный факт;
- «мы внесли один текст и считаем, что он действовал всегда» — допущение.

Хранятся они одинаково: одна редакция с `effective_from: 1996-07-01` и
пустым `effective_to`. Разница принципиальная: во втором случае на дату
из прошлого система вернёт **не ту** редакцию, причём уверенно и со
статусом `verified` — то есть ровно тот отказ, который продукт обещает
предотвращать. Пробел в покрытии безопаснее: он даёт честную ошибку
`NoApplicableVersionError`.

## Как читать отчёт

Норма попадает в список на сверку, если выполнено одно из условий:

- **разрыв** между редакциями — на дату внутри дыры норма не найдётся;
- **одна открытая редакция дольше 10 лет** у нормы,
  которую читает движок правил, — история изменений не зафиксирована.

Значимой для правил считается норма, у которой есть структурные пределы
санкции либо на которую правило ссылается по `norm_id`
(`rule_engine.rules.REFERENCED_NORM_IDS`; расхождение со ссылками в коде
ловит `tests/unit/test_norm_coverage.py`).

## Что сделать по каждой норме

1. Поднять историю изменений статьи по официальному источнику
   (КонсультантПлюс / pravo.gov.ru) за период с даты в колонке
   «Заявлено с» по настоящее время.
2. Если статья **действительно не менялась** — зафиксировать это: в `note`
   файла указать дату сверки истории и источник. Тогда единственная
   редакция становится подтверждённым фактом, а не допущением.
3. Если менялась — внести недостающие редакции по правилам
   `docs/DATA_SOURCES.md`: точные границы `effective_from` / `effective_to`,
   `source_url`, `retrieved_at`, обновлённые `sanctions`.
4. Прогнать `make test` и `second-opinion norms-coverage`.

Тексты редакций вносит юрист по официальному источнику. Заполнение
«по памяти» запрещено `docs/DATA_SOURCES.md` и в судебной системе
недопустимо.

## Чего отчёт не проверяет

- **корректность самих текстов** — только полноту редакционных интервалов;
- **актуальность действующей редакции**: нормы сверены по КП 03.09.2026,
  более поздние поправки отчёт не увидит;
- **целостность файла фикстуры**: `sha256` хранится как `AUTOFILL` и
  вычисляется при загрузке из того же текста, поэтому контрольная сумма
  подтверждает согласованность в памяти, но не защищает файл от правки.
