# LEGAL_SAFETY_PRINCIPLES

Обязательные принципы юридической безопасности. Любой код, нарушающий эти
принципы, считается дефектным независимо от результатов тестов.

## 1. Приоритет человека (human authority)

Система — инструмент проверки, не источник власти. Запрещены формулировки
«система определила/рекомендует наказание». Допустимы: «обнаружены
обстоятельства…», «применима норма…», «проверка выявила возможное
расхождение…», «в выборке из N дел распределение…». Решение всегда остаётся
за судьёй; интерфейс явно это фиксирует.

## 2. Прослеживаемость (traceability)

Каждое юридически значимое утверждение должно раскрываться по цепочке:

```
вывод → факт → фрагмент исходного документа (оффсеты) → норма →
редакция нормы → официальный источник → судебная практика (если используется)
```

Тест-инвариант: в отчёте не существует утверждения со статусом `VERIFIED`
без непустого `evidence`, чья цитата действительно присутствует в тексте
документа по указанным оффсетам.

## 3. Источник прежде всего (source provenance)

LLM не является источником права. Тексты норм, постановлений Пленума и
обзоров берутся из хранилища источников; каждый источник имеет: официальный
реквизит, дату извлечения (`retrieved_at`), SHA-256 контрольную сумму.
Если источник не найден — система сообщает `NOT_FOUND`, а не генерирует текст.

## 4. Временна́я корректность (temporal validity)

Норма применяется в редакции, действовавшей на юридически значимую дату
(`applicable_at`). Запрещено молча применять текущую редакцию к прошлому
делу. Если на дату нет ни одной версии нормы — статус `UNKNOWN` с явным
сообщением, не догадка.

## 5. Неопределённость (uncertainty)

Пятиуровневая шкала статусов: `VERIFIED`, `LIKELY`, `UNCERTAIN`,
`NOT_FOUND`, `CONFLICT`. Понижение статуса обязательно при: низком качестве
извлечения, противоречивых фрагментах, отсутствии источника. Статус
отображается в UI и сериализуется в отчёт.

## 6. Противодействие галлюцинациям (hallucination mitigation)

- Норма права никогда не генерируется моделью — только извлекается из базы.
- Структурированный вывод валидируется схемой; невалидный JSON — повторная
  попытка, затем `UNKNOWN`, никогда «правдоподобная догадка».
- Правило-движок детерминирован и покрыт регрессионными тестами.
- Метрика `unsupported_claim_rate` стремится к 0 и измеряется на каждом
  evaluation-прогоне.

## 7. Смещения (bias)

Статистика по историческим делам может воспроизводить системные смещения.
Поэтому: статистика только описательная; никакие признаки личности
(имя, пол, происхождение) не участвуют в ранжировании как значимые;
выборка дел показывается судье прозрачно (по каким признакам дело отобрано).

## 8. Приватность (privacy)

- Работаем с обезличенными текстами (публикация по 262-ФЗ уже обезличена);
  в фикстурах — только синтетические дела, явно маркированные.
- Извлечённые персональные фрагменты не логируются целиком: журнал содержит
  хэши и идентификаторы, не сырой текст документа.

## 9. Конфиденциальность (confidentiality)

Реальные материалы дел не покидают контур системы: внешние LLM-вызовы
выключены по умолчанию (провайдер `mock`). Отправка текста во внешний
провайдер возможна только при явном включении режима
(`SO_LLM_PROVIDER != mock`) и информированном согласии оператора.

## 10. Безопасность (security)

Текст документа — **недоверенные данные** (untrusted data). Содержимое
«Игнорируй предыдущие инструкции» внутри судебного акта не влияет на
поведение модели: системные инструкции отделены от текста документа,
документ подаётся как данные (см. `prompts/`). Дополнительные угрозы — в
`docs/SECURITY.md` (prompt injection, RAG poisoning, вредоносный PDF,
утечка ключей; появится в M10).

## 11. Воспроизводимость (reproducibility)

Audit trail фиксирует: версию модели, версию промпта, версию правил,
версии норм, хэши входа и выхода каждого шага. Отчёт, полученный на тех же
версиях и данных, обязан быть побитово идентичным для детерминированных
компонентов (парсер, правило-движок, поиск по фильтрам).
