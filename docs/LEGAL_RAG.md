# LEGAL_RAG

Поиск по базе источников: нормы УК РФ и УПК РФ (фикстуры) с редакциями
и реквизитами. Поиск — лексический, детерминированный, без LLM, с
опциональным гибридным реранкингом.

## Инвариант источника

Результат поиска **всегда** является фрагментом реально хранящейся
редакции нормы. Если ничего не найдено — возвращается пустой результат,
а не сгенерированный ответ. Целостность цитирования контролируется
метрикой `citation_integrity` (=1.0) в `make eval` (docs/EVALUATION.md).

## Как работает

```text
запрос -> токенизация (стоп-слова «ук/рф/статья…», цифры, слова ≥3 букв)
       -> выбор корпуса: для каждой нормы — редакция на applicable_at
         (или текущая, если дата не задана)
       -> IDF по корпусу выбранных редакций
       -> «ё» читается как «е» («грабёж» = «грабеж» в тексте ИПС)
       -> скоринг: точное совпадение (×1.25 в заголовке) / префикс-флексия (×0.75);
          одно совпадение только по началу слова при запросе из нескольких
          слов находкой не считается
       -> поправка на длину текста (BM25: k1 = 1,2, b = 0,75)
       -> черновик ×0,85: при близкой релевантности сверенный источник выше
       -> ранжирование -> SearchHit[]
```

`SearchHit` несёт полный провенанс: norm_id, version_id, текст фрагмента,
период действия, источник (`source_document`, `source_url`),
`retrieved_at`, SHA-256, статус верификации и признак синтетичности.

## Метаданные-фильтры

| Фильтр | Значение |
|---|---|
| `code` | «УК РФ», «УПК РФ»… |
| `article` | номер статьи |
| `applicable_at` | ISO-дата; выбирает редакцию, действовавшую на дату |

## API

Явный запрос УК РФ может получать отсутствующую статью из ИПС при
`SO_DYNAMIC_NORM_SOURCE=pravo`. В интерфейсе «Источники» доступны поля
статьи, части и даты. `q` в этом сценарии необязателен:

```http
GET /api/v1/search?code=УК%20РФ&article=272&part=1&applicable_at=2022-05-10
```

Дополнительный `source_state` содержит состояние применимости/актуальности
и снимки. Неопределённый внешний текст возвращается в `candidate`,
отдельно от `SearchHit`: обязательная дата начала действия не выдумывается.
Ниже — сокращённый пример формы ответа тестового сервера, не живая норма:

```json

    "applicable_at": "2022-05-10",
    "applicability": "unknown",
    "freshness": "unknown",
    "structured_data": "missing",
    "acquisition": "fetched",
    "candidate": {
      "provider": "pravo",
      "document_id": "102041891",
      "edition_id": "2",
      "article": "272",
```

Полный ответ также содержит SHA-256 полного текста фрагмента и причины

[DATA_SOURCES](DATA_SOURCES.md#динамическое-получение-ук-рф). Обычный запрос
по словам продолжает пользоваться лексическим/гибридным индексом корпуса.


## Ограничения и развитие

- Корпус: сверенные нормы УК (Общая и Особенная часть), УПК (ст. 316, 420),
  ППВС № 58 (пп. 1, 34, 36) и № 60 (пп. 7, 13, 14); черновики — 26 пунктов
  ППВС № 58, 10 позиций Обзора ВС РФ, 44 части статей Особенной части и
  ст. 10, 68, 88, 89 из ИПС, глава 11 и ст. 78; синтетическая демо-норма
  (docs/DATA_SOURCES.md).
- Без даты ищутся действующие редакции. Норма без действующей редакции (часть
  статьи, которой в нынешнем тексте нет, например ст. 228 ч. 4 редакции 1996
  года) находится только поиском на дату, когда она действовала.
- Текст сверенной части статьи — выверенная запись санкции без описания
  деяния. По словам диспозиции такая норма находится через поле `search_text`
  (название статьи и диспозиция части по действующему тексту ИПС); поле
  участвует только в поиске, во фрагмент выдачи и в заключение не попадает.
- Качество поиска измеряется Recall@5/MRR/nDCG@10 на датасете
  `retrieval_v1.json` (docs/EVALUATION.md), отдельно для обоих режимов.

## Гибридный режим (опционально)

`SO_RAG_MODE=hybrid` включает реранкинг лексических кандидатов: лексическая
и семантическая (косинусная близость) оценки приводятся к шкале 0..1 внутри
выдачи и складываются с весами 0,7 и 0,3. Слияние по местам (Reciprocal Rank
Fusion) стирало разрыв в оценках — норма с лексической оценкой 0,31 и норма с
0,11 получали почти одинаковый вклад, — и слабый сигнал хэширующего
векторизатора переставлял выдачу.

- Провайдер векторизации: `HashingTfidfEmbedder` (по умолчанию) —
  детерминированный офлайн-векторизатор: символьные n-граммы 3–5 + слова,
  хэш в 1024 измерения, сублинейный вес частоты, L2-нормализация.
  Поведение воспроизводимо без сети и моделей.
- `SO_EMBEDDINGS_PROVIDER=openai_compatible` — сервер векторизации в
  закрытом контуре; адрес проверяется так же, как адрес модели
  (`llm/contour.py`).

Реранкинг меняет только порядок уже найденных кандидатов и не может
добавить фрагмент, отсутствующий в хранилище. В гибридном режиме каждый
хит дополнительно несёт `lexical_score` и `semantic_score`.

**Качество на контрольном наборе** (`retrieval_v1.json`, 28 запросов, из них
10 — к пунктам Пленума № 58 и позициям Обзора ВС РФ; `second-opinion eval`):

| Режим | Recall@5 | MRR | nDCG@10 |
|---|---|---|---|
| лексический (по умолчанию) | 0,955 | 0,944 | 0,920 |
| гибридный | 0,955 | 0,963 | 0,936 |

Два запроса находятся не полностью. В q21 («рецидив одна треть максимального
срока») п. 47 ППВС № 58 на 7-м месте: «одна треть» в запросе и «одной трети»
в тексте не совпадают ни целиком, ни по основе из шести букв. В q27
(«несовершеннолетний покушение особо крупный размер») позиция Обзора говорит
«ч. 3 ст. 30, п. „г“ ч. 4 ст. 228¹» — синонимов юридических формулировок поиск
не знает. В лексическом режиме q11 («умышленное причинение тяжкого вреда
здоровью потерпевшего») ставит ч. 4 ст. 111 выше ч. 1: слово «потерпевшего» есть
только в ч. 4. Правило «основа без последней буквы» для коротких слов
проверялось и ухудшило выдачу (новый провал q17), поэтому не принято.

Гибридный режим на этом наборе точнее по MRR и nDCG при той же полноте. По
умолчанию остаётся лексический: в его выдаче у каждой нормы видны слова
запроса, по которым она найдена, а вклад векторной близости судье объяснить
нечем.
