# PRODUCT_VISION — «Второе мнение»

Система поддержки принятия судебных решений для конкурса Верховного Суда РФ
«Алгоритм правосудия. Второе мнение».

## Проблема

Назначение наказания — многошаговая юридическая проверка: санкция статьи,
правила Общей части УК (ст. 60–73), разъяснения Пленума ВС РФ, сопоставимая
практика. Судья выполняет эту проверку вручную под высокой нагрузкой;
часть ограничений (пределы при неоконченном преступлении, особом порядке,
смягчающих обстоятельствах) легко проверить формально, но на это уходит время.

## Целевые пользователи

- Судьи (основной пользователь) — проверяют проект судебного акта.
- Помощники судей и аппарат суда — подготовка материалов.
- В перспективе: стороны процесса в режиме ознакомления (вне скоупа MVP).

## Что это

Верифицируемая система **юридического аудита** проекта судебного акта:

1. извлекает юридически значимые обстоятельства с привязкой к цитатам;
2. выполняет детерминированные проверки применимых норм;
3. показывает применимые нормы в правильной редакции (по дате);
4. подбирает сопоставимые дела как справочный материал;
5. даёт описательную статистику по выборке — без рекомендаций о наказании.

## Что это НЕ (NON-GOALS)

Мы **не**:

- заменяем судью и не принимаем решений за него;
- не назначаем наказание и не выдаём «правильный срок»;
- не выдаём вывод системы за обязательный;
- не используем статистику как нормативный источник (она только описательная);
- не строим скоринг/рейтинг подсудимых или судов;
- не заменяем юридическую оценку человека предсказанием модели.

## Принципы

1. **Объяснимость как конструкция.** Каждый вывод раскладывается:
   вывод → факт → цитата из документа → норма → редакция → источник.
2. **Источник прежде всего.** Норма права приходит из базы источников,
   а не генерируется LLM. LLM — инструмент извлечения и пояснения.
3. **Детерминизм там, где возможен.** Формализуемые проверки — в Rule Engine,
   не в промпт.
4. **Временна́я корректность.** К делу 2022 года применяется редакция нормы,
   действовавшая на юридически значимую дату.
5. **Человек в контуре.** Каждый извлечённый факт показывается, связан с
   цитатой и исправим пользователем.
6. **Безопасный отказ.** Не уверен — не выдумывай: статусы
   `VERIFIED / LIKELY / UNCERTAIN / NOT_FOUND / CONFLICT`.

## Пользовательский сценарий (кратко)

1. Судья загружает проект судебного акта (текст/файл).
2. Система показывает карточку дела и извлечённые обстоятельства.
3. Судья кликает на обстоятельство — видит точную цитату из документа.
4. Система показывает результаты формальных проверок (`✓ / ⚠ / ✗ / ?`).
5. Судья раскрывает проверку — видит: правило → использованные факты →
   норму → текст нормы → редакцию → источник → объяснение срабатывания.
6. Система показывает сопоставимые дела и описательную статистику по ним.
7. Судья принимает решение **сам**; система лишь предоставляет материалы.

## Ценностное предложение

- Снижение риска пропустить формальное ограничение при назначении наказания.
- Экономия времени на подборе применимых норм и практики.
- Полная проверяемость каждого утверждения системы — ключевое требование
   конкурса и судов.
