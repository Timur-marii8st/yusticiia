## Working

- **Запуск одной командой:** `second-opinion serve` (или `make dev`) —
  поднимает API + UI на http://127.0.0.1:8000. Проверено: сервер стартует,
  эндпоинты отвечают.
- **Document ingestion:** TXT, Markdown, DOCX, PDF с текстовым слоем
  + опциональный OCR-фолбэк для сканов (скан без текстового слоя
  распознаётся Tesseract, если установлены `tesseract-ocr` + зависимости
  группы `ocr`; иначе — честный отказ с подсказкой). Нормализация текста,
  SHA-256, оффсеты/страницы, лимит размера, отказ на пустые/бинарные/
  неподдерживаемые файлы. Проверено тестами (фикстуры PDF/DOCX, mock-OCR).
- **Fact extraction (паттерны):** квалификация, возраст, судимости,
  несовершеннолетние дети, здоровье, стадия, групповое деяние
  (группа лиц / предварительный сговор / организованная группа — с
  детерминированным выбором сильнейшей формы), признание вины, явка с
  повинной/способствование, возмещение ущерба, рецидив, особый порядок,
  присяжные, вид/размер наказания, условность, дата совершения.
  Каждый факт несёт evidence с точными оффсетами; статус `VERIFIED`.
- **Fact extraction (LLM):** за интерфейсом `LLMProvider`; структурированный
  вывод валидируется схемой; цитаты, не найденные в тексте, отбрасываются;
  `MockLLMProvider` по умолчанию (полностью офлайн). Адаптер
  `OpenAICompatibleProvider` реализован, включается явно.
- **Temporal legal store:** `get_norm(norm_id, applicable_at)` с проверкой
  интервалов редакций, контрольными суммами и явными ошибками. Границы дат
  покрыты тестами. Есть синтетическая двухредакционная норма для демо.
- **Rule Engine — 8 детерминированных правил (v2.0.0, сверено 03.09.2026):**
  R-001 пределы санкции (ст. 60); R-002 неоконченное преступление
  (ст. 66: покушение ≤ 3/4, приготовление ≤ 1/2); R-003 особый порядок
  (ч. 5 ст. 62 УК + ч. 7 ст. 316 УПК, п. 13 ППВС № 60); R-004 смягчающие
  пп. «и»/«к» без отягчающих (ст. 62 ч. 1, усл. п. 36 ППВС № 58);
  R-006 условное осуждение (ч. 1 ст. 73: ≤ 8 лет);
  R-007 общий порядок по делам несовершеннолетних (ч. 2 ст. 420 УПК +
  п. 7 ППВС № 60); R-009 полнота данных о наказании (структурная проверка
  без толкования норм: WARNING, если извлечён только вид или только размер);
  R-010 неоконченное в особом порядке: M × доля ст. 66 × 2/3 (п. 14 ППВС № 60).
  Удалены ложные R-005 («1/3 по ч. 3 ст. 62» — такой дроби нет) и R-008
  («неучёт рецидива по ч. 2 ст. 63» — статья о другом; блокировку ч. 1
  ст. 62 рецидивом покрывает R-004). Подробности — CHANGELOG 0.22.
  Статусы PASS/WARNING/FAIL/UNKNOWN; каждая оценка несёт `facts_used`,
  `norms_used` (с версией редакции), численный расчёт и объяснение.
- **Case retrieval:** структурные фильтры + взвешенное ранжирование; каждое
  дело сопровождается `reasons[]`; без «процентов сходства». База —
  26 синтетических дел (ст. 111, 112, 158, 159, 161, 163, 228: стадии,
  рецидив, присяжные, особый порядок, групповые деяния). Отбор строгий:
  если по документу извлечены содержательные признаки, но ни один не
  совпал — дело НЕ считается сопоставимым. Критерии: часть, стадия,
  процедура, рецидив, присяжные, группа/сговор, смягчающие.
- **Временно́й механизм на сквозном демо:** один документ по синтетической
  ст. 999 (48 мес.) даёт R-001=FAIL на дате 2022 (редакция v2020, максимум
  36) и R-001=PASS на дате 2025 (v2024, максимум 60); выбранная редакция
  видна в `norms_applied`. Дата из документа без явного указания сама
  выбирает старую редакцию. Интеграционный тест фиксирует все три ветки.
- **Аналитика:** описательная статистика (медиана, перцентили,
  распределение, доля условного) с явными дисклеймерами.
- **Legal RAG (лексический поиск по источникам):** `GET /api/search?q=…`
  (+ фильтры `код`, `статья`, `applicable_at`): токенизация со стоп-словами
  и учётом словоформ, выбор редакции нормы на дату, IDF-ранжирование по
  корпусу редакций. Каждый результат — фрагмент реально хранящегося
  источника с редакцией, периодом действия, реквизитами и SHA-256; если
  ничего не найдено — честный пустой ответ. Раздел «Источники» с поиском —
  в UI. Проверено смоук-тестом на живом сервере.
- **Гибридный реранкинг (опция, ADR-003):** `SO_RAG_MODE=hybrid` — RRF-фьюжн
  лексического и семантического ранжирований; офлайн детерминированный
  `HashingTfidfEmbedder` по умолчанию, внешний `/embeddings` — только явно.
  Реранкинг меняет порядок найденного, но не добавляет новых фрагментов;
  оба режима измеряются в `make eval`. Дефолт — `lexical`: на текущем
  корпусе он точнее (MRR 0.958 против 0.896), измерение зафиксировано
  в ADR-003 и docs/LEGAL_RAG.md.
- **Rule Engine — 8 правил (v2.0.0, сверено 03.09.2026):** исправлены ссылки
  R-003 (ч. 5 ст. 62 + ч. 7 ст. 316 вместо ч. 2 ст. 62), R-006 (ч. 1 ст. 73
  вместо ч. 3), R-007 (добавлен п. 7 ППВС № 60 как оперативное основание);
  удалены ложные R-005 и R-008 (см. выше); добавлено R-010
  «неоконченное в особом порядке» (п. 14 ППВС № 60) и структурное R-009.
  Регрессий — 39 сценариев; добавлены нормы 112 ч. 1, 163 ч. 1, 316 ч. 7,
  ППВС № 60 пп. 7/13/14, ППВС № 58 п. 36; исправлена фикстура ППВС № 58
  п. 34 (порядок исчисления пределов, а не условное осуждение).
- **Человек в контуре (коррекция фактов):** судья может подтвердить
  (`VERIFIED`), исключить из проверок (`NOT_FOUND`) или исправить значение
  любого извлечённого факта (`PATCH /api/analyses/{id}/facts/{fact_id}`);
  отчёт детерминированно пересчитывается правило-движком, поиск практики и
  аналитика обновляются; правка логируется в аудит-журнал; исключённые
  факты остаются видимыми в истории. Кнопки «Подтвердить» / «Исключить из
  проверок» — в UI.
- **Человек в контуре (добавление обстоятельств):** судья добавляет факт
  «с нуля» (`POST /api/analyses/{id}/facts`: тип + значение + цитата).
  Инвариант тот же: цитата обязана дословно находиться в документе, иначе
  отказ (400); значение проверяется по схеме типа (числа, булевы,
  перечисления, квалификация); факт создаётся VERIFIED с методом `user` и
  сразу участвует в пересчёте проверок. Форма «Добавить обстоятельство» —
  в UI с вводом значения по типу.

## Known limitations

1. Фикстуры норм сверены юристом по КП 03.09.2026 (`verified`), но это
   точные изложения со ссылкой на первоисточник, а не официальный текст:
   перед судебной демонстрацией — контрольная сверка с КП. Сознательно не
   реконструированы: поэлементные альтернативы ФЗ № 26-ФЗ, дореформенная
   ст. 228, поздние расширения исключений ч. 1 ст. 73.
2. Все сопоставимые дела — синтетические; маркируются в данных и в UI.
3. Паттерны извлечения ориентированы на типовые формулировки приговоров;
   нестандартные тексты могут давать неполное извлечение (статусы
   `UNKNOWN` у правил это отражают).
4. Файловое хранилище по умолчанию: один процесс, без транзакций
   (осознанное решение MVP, ADR-006); postgres-бэкенд (`SO_STORAGE_BACKEND=postgres`)
   снимает ограничение, но требует отдельной эксплуатации БД.
5. `ч. 3 ст. 30 УК РФ` в квалификациях игнорируется (норма Общей части);
   статья определяется по последней ссылке вида «ч. N ст. N УК».
6. Гибридный реранкинг на малом корпусе уступает лексическому (измерено);
   дефолт — lexical, переключение — по метрикам после роста корпуса.
7. R-007 опирается на возраст из документа; если указан возраст на момент
   рассмотрения, а не на момент деяния, требуется ручная проверка
   (отмечено в объяснении правила).
8. Доли ст. 62/66 зашиты в код правил (2/3, 1/2, 3/4 действующих редакций):
   для дел до 07.2009 по ст. 62 действовал предел 3/4 — движок его не
   применяет (верная редакция нормы подбирается и показывается, но расчёт
   идёт по действующим долям; требуется ручная проверка).
