# IMPLEMENTATION_STATUS

Обновлено: 2026-08-26 (итерация 12: опциональная Bearer-авторизация API
(SO_AUTH_TOKEN) с формой входа в UI; смок-тест производительности на
большом документе; ранее: конкурентная надёжность хранилища, печать/JSON,
право на забвение, добавление фактов судьёй, M9, M10, M6, M5).

## Working

- **Запуск одной командой:** `second-opinion serve` (или `make dev`) —
  поднимает API + UI на http://127.0.0.1:8000. Проверено: сервер стартует,
  эндпоинты отвечают.
- **Document ingestion:** TXT, Markdown, DOCX, PDF с текстовым слоем.
  Нормализация текста, SHA-256 документа, оффсеты/страницы, лимит размера,
  отказ на пустые/бинарные/неподдерживаемые файлы. Проверено тестами,
  включая сгенерированные PDF/DOCX-фикстуры.
- **Fact extraction (паттерны):** квалификация, возраст, судимости,
  несовершеннолетние дети, здоровье, стадия, групповое деяние
  (группа лиц / предварительный сговор / организованная группа — с
  детерминированным выбором сильнейшей формы), признание вины, явка с
  повинной/способствование, возмещение ущерба, рецидив, особый порядок,
  присяжные, вид/размер наказания, условность, дата совершения.
  Каждый факт несёт evidence с точными оффсетами; статус `VERIFIED`.
- **Fact extraction (LLM):** за интерфейсом `LLMProvider`; структурированный
  вывод валидируется схемой; цитаты, не найденные в тексте, отбрасываются;
  `MockLLMProvider` по умолчанию (полностью офлайн). Адаптер
  `OpenAICompatibleProvider` реализован, включается явно.
- **Temporal legal store:** `get_norm(norm_id, applicable_at)` с проверкой
  интервалов редакций, контрольными суммами и явными ошибками. Границы дат
  покрыты тестами. Есть синтетическая двухредакционная норма для демо.
- **Rule Engine — 6 детерминированных правил:**
  R-001 пределы санкции (ст. 60); R-002 неоконченное преступление
  (ст. 66: покушение ≤ 3/4, приготовление ≤ 1/2); R-003 особый порядок
  (ст. 62 ч. 2); R-004 смягчающие пп. «и»/«к» (ст. 62 ч. 1); R-005
  совокупный предел (ст. 62 ч. 3); R-006 условное осуждение (ст. 73 ч. 3).
  Статусы PASS/WARNING/FAIL/UNKNOWN; каждая оценка несёт `facts_used`,
  `norms_used` (с версией редакции), численный расчёт и объяснение.
  24 юнит-теста, включая граничные значения.
- **Case retrieval:** структурные фильтры + взвешенное ранжирование; каждое
  дело сопровождается `reasons[]`; без «процентов сходства». База —
  22 синтетических дела (ст. 111, 112, 158, 159, 161, 163, 228: стадии,
  рецидив, присяжные, особый порядок, групповые деяния). Отбор строгий:
  если по документу извлечены содержательные признаки, но ни один не
  совпал — дело НЕ считается сопоставимым. Критерии: часть, стадия,
  процедура, рецидив, присяжные, группа/сговор, смягчающие.
- **Временно́й механизм на сквозном демо:** один документ по синтетической
  ст. 999 (48 мес.) даёт R-001=FAIL на дате 2022 (редакция v2020, максимум
  36) и R-001=PASS на дате 2025 (v2024, максимум 60); выбранная редакция
  видна в `norms_applied`. Дата из документа без явного указания сама
  выбирает старую редакцию. Интеграционный тест фиксирует все три ветки.
- **Аналитика:** описательная статистика (медиана, перцентили,
  распределение, доля условного) с явными дисклеймерами.
- **Legal RAG (лексический поиск по источникам):** `GET /api/search?q=…`
  (+ фильтры `код`, `статья`, `applicable_at`): токенизация со стоп-словами
  и учётом словоформ, выбор редакции нормы на дату, IDF-ранжирование по
  корпусу редакций. Каждый результат — фрагмент реально хранящегося
  источника с редакцией, периодом действия, реквизитами и SHA-256; если
  ничего не найдено — честный пустой ответ. Раздел «Источники» с поиском —
  в UI. Проверено смоук-тестом на живом сервере.
- **Гибридный реранкинг (опция, ADR-003):** `SO_RAG_MODE=hybrid` — RRF-фьюжн
  лексического и семантического ранжирований; офлайн детерминированный
  `HashingTfidfEmbedder` по умолчанию, внешний `/embeddings` — только явно.
  Реранкинг меняет порядок найденного, но не добавляет новых фрагментов;
  оба режима измеряются в `make eval`. Дефолт — `lexical`: на текущем
  корпусе он точнее (MRR 0.958 против 0.896), измерение зафиксировано
  в ADR-003 и docs/LEGAL_RAG.md.
- **Rule Engine — 8 правил (v1.1.0):** добавлены R-007 «особый порядок и
  несовершеннолетие» (ч. 2 ст. 420 УПК РФ: FAIL при сочетании) и R-008
  «рецидив + смягчающие пп. „и“/„к“» (ч. 2 ст. 63 УК РФ: WARNING — отягчающее
  не учитывается). Каждое с регрессионными тестами; в хранилище добавлена
  черновая норма УПК ст. 420.
- **Человек в контуре (коррекция фактов):** судья может подтвердить
  (`VERIFIED`), исключить из проверок (`NOT_FOUND`) или исправить значение
  любого извлечённого факта (`PATCH /api/analyses/{id}/facts/{fact_id}`);
  отчёт детерминированно пересчитывается правило-движком, поиск практики и
  аналитика обновляются; правка логируется в аудит-журнал; исключённые
  факты остаются видимыми в истории. Кнопки «Подтвердить» / «Исключить из
  проверок» — в UI.
- **Человек в контуре (добавление обстоятельств):** судья добавляет факт
  «с нуля» (`POST /api/analyses/{id}/facts`: тип + значение + цитата).
  Инвариант тот же: цитата обязана дословно находиться в документе, иначе
  отказ (400); значение проверяется по схеме типа (числа, булевы,
  перечисления, квалификация); факт создаётся VERIFIED с методом `user` и
  сразу участвует в пересчёте проверок. Форма «Добавить обстоятельство» —
  в UI с вводом значения по типу.
- **Проведена полная проверка:** 200 тестов зелёных; `ruff check` чистый;
  `second-opinion eval`: macro-F1 = 1.0 на 8 образцах (включая негативный
  контроль и временный), evidence correctness = 1.0,
  `unsupported_claim_rate` = 0, Recall@5/MRR/nDCG в обоих режимах поиска
  выше порогов; `pip-audit` — без известных уязвимостей (CI блокирующий).
- **UI:** статический экран анализа (прогрессивное раскрытие: обстоятельство
  → цитата → правило → норма → редакция), раздаётся приложением. Проверен
  смоук-тестом через HTTP (index/js/css/демо-документ отдаются). У каждого
  обстоятельства показывается обратная связь «Учитывается при следующих
  проверках» (факт → статусы и заголовки проверок правила-движка) — сценарий
  демонстрации §29 ТЗ закрыт.
- **Наблюдаемость:** структурные логи стадий конвейера
  (`logging_utils.log_stage`): request_id, стадия, длительность, счётчики;
  тексты документов в логи не попадают по построению (тест на многострочность).
- **Воспроизводимость:** интеграционный тест — два независимых конвейера
  дают идентичный содержательный результат (факты/оценки/аналитика/дела)
  на одном документе; волатильные связи (document_id) исключены из сравнения.
- **Краевые образцы + регрессия:** новые синтетические приговоры покрывают
  конфликт «16 лет × особый порядок» (R-007=FAIL), сочетание
  «рецидив × пп. „и“/„к“» (R-008=WARNING) и границу ч. 3 ст. 73 (условное
  ровно при 96 мес. → PASS, предел включён); все вошли в evaluation-корпус
  с золотой разметкой. Исправлены паттерны: `рецидив` в конце строки не
  распознавался (`\w+` → `\w*`); добавлена форма «ранее дважды судим»
  (отрицание «ранее не судим» по-прежнему не даёт факта). В корпус норм
  добавлена черновая санкция ч. 2 ст. 161 УК РФ.
- **Аудит-журнал:** JSONL, фиксирует версии правил/промптов/модели, хэши
  входа/выхода; без сырых текстов документов.
- **Право на забвение:** `DELETE /api/documents/{id}` удаляет документ и
  все отчёты по нему (каскад); `DELETE /api/analyses/{id}` — отдельный
  отчёт; операции фиксируются в аудите без текстов. Покрыто тестами.
- **Supply-chain:** pip-audit локально чист; CI-джоб аудита переведён в
  блокирующий режим (setuptools в CI обновляется перед проверкой).
- **Надёжность хранилища:** тесты конкурентного доступа — параллельные
  ingest/analyze разных документов и параллельные анализы одного
  документа (sync-эндпоинты FastAPI работают в threadpool): отчёты не
  теряются и не повреждаются, идентификаторы уникальны.
- **UX отчёта:** печатная версия (@media print — только содержательные
  разделы), кнопка «Печать отчёта» и выгрузка JSON отчёта.
- **Документация API:** docs/API.md — справочник эндпоинтов с инвариантами;
  CHANGELOG.md — история итераций.
- **Авторизация (опционально):** `SO_AUTH_TOKEN` включает Bearer-проверку
  всех `/api/*` (401 без валидного токена; `/health`, статика и UI
  открыты). UI показывает форму входа при 401 и хранит токен в sessionStorage.
  Закрывает базовый уровень для сетевого развертывания за прокси
  (SECURITY.md п. 6: «частично»); персональные учётные записи — в ROADMAP.
- **Производительность:** смок-тест на документе ~175 тыс. символов:
  полный анализ < 1 с (порог 15 с против регрессий порядка величины).
- **Документация:** README, PRODUCT_VISION, ARCHITECTURE,
  LEGAL_SAFETY_PRINCIPLES, DOMAIN_MODEL, IMPLEMENTATION_PLAN,
  CURRENT_STATE, ADR-001…007, CI (GitHub Actions: lint + tests).

- **Evaluation — полный набор (M9):** к метрикам извлечения (macro-F1,
  evidence correctness, `unsupported_claim_rate`, per-type P/R/F1) добавлены:
  поиск по источникам — Recall@5 / MRR / nDCG@10 на датасете
  `retrieval_v1.json` (13 запросов, включая честный пустой ответ), в обоих
  режимах; целостность цитирования (фрагмент = реально хранящаяся редакция
  + SHA-256 сходится), временно́й блок — точность выбора редакции на дату,
  включая граничные даты интервалов. Пороги приёмки проверяются кодом
  возврата (`make eval`).
- **Корпус evaluation расширен:** новый образец мошенничества
  (159 ч. 2: явка с повинной, возмещение, рецидив судимости) и негативный
  контроль — процессуальный документ без обстоятельств дела, корректное
  извлечение = пусто. Устойчивость паттерна возмещения расширена
  («возместил причинённый ущерб»).
- **Безопасность и эксплуатация (M10):** модель угроз с статусами мер
  (prompt injection, RAG poisoning, вредоносный PDF, утечка PII/ключей,
  несанкционированный доступ, логирование, supply-chain) —
  docs/SECURITY.md; режимы обращения с данными — docs/PRIVACY.md; профили

- **Docker:** Dockerfile + docker-compose.yml (один контейнер, том для
  данных, публикация только на loopback). Проверено end-to-end: сборка,
  загрузка документа через multipart, анализ (11 фактов, 6 проверок,

- **Исправлены дефекты упаковки** (обнаружены при docker-проверке):
  промпты перенесены внутрь пакета (`src/second_opinion/prompts/`, путь
  резолвится относительно модуля — работает при pip-установке);

- **Документация дополнена:** RULE_ENGINE.md (реестр правил + процедура
  добавления), LEGAL_RAG.md (механика поиска, инвариант источника),

## Partially working

- **Корпус источников для RAG:** поиск работает по базе норм (УК РФ,
  черновые санкции + синтетические редакции); тексты постановлений Пленума
  и обзоров практики ещё не внесены — их добавление требует юридической
  сверки (это данные, не код).
- **Редакции реальных норм:** в фикстурах у реальных статей одна
  «текущая» версия (`verification_status: draft`); исторические редакции
  реальных норм наполняются отдельно (юридическая сверка). Механизм выбора
  редакции по дате полностью готов (показан на синтетической двухредакционной
  норме).
- **LLM-экстрактор в демо-режиме:** мок-провайдер не добавляет фактов
  (честный офлайн-дефолт); реальный провайдер требует внешней настройки и
  пока не прогонялся на живых документах.

## Not implemented

- OCR; эмбеддинги/реранкинг по умолчанию (гибридный режим реализован как
  опция, ADR-003); личный кабинет;
  PostgreSQL/pgvector; перевод pip-audit в блокирующий режим
  (dependabot уже подключён).

## Tests

- 209 автотестов: доменные инварианты (включая «факт без evidence ≠
  VERIFIED»), парсеры (TXT/MD/DOCX/PDF, включая негативные), временной
  выбор редакций + сквозное демо «документ × редакция → исход проверки»,
  паттерновый и LLM-экстракторы (включая невалидный JSON, отсутствующие
  цитаты, негативный контроль, краевые формулировки и формы группы),
  37 регрессионных сценария правило-движка (8 правил), поиск дел
  (включая групповой критерий), аналитика, сквозной конвейер +
  воспроизводимость + конкурентная надёжность + большой документ,
  коррекция фактов с пересчётом, добавление фактов судьёй, удаление
  документов/отчётов (каскад, аудит), авторизация API (токен/401/публичные
  пути), лексический и гибридный поиск по источникам, метрики evaluation,
  структурные логи, интеграция с API.
- Injection-тест: инструкция «Ignore previous instructions…» в тексте
  документа не добавляет фактов.

## Known limitations

1. Санкции в фикстурах — черновые (`draft`); обязательна сверка с
   официальным источником до демонстраций. Норма УПК ст. 420 — тоже черновик.
2. Все сопоставимые дела — синтетические; маркируются в данных и в UI.
3. Паттерны извлечения ориентированы на типовые формулировки приговоров;
   нестандартные тексты могут давать неполное извлечение (статусы
   `UNKNOWN` у правил это отражают).
4. Файловое хранилище: один процесс, без транзакций (осознанное решение
   MVP, ADR-006).
5. `ч. 3 ст. 30 УК РФ` в квалификациях игнорируется (норма Общей части);
   статья определяется по последней ссылке вида «ч. N ст. N УК».
6. Гибридный реранкинг на малом корпусе уступает лексическому (измерено);
   дефолт — lexical, переключение — по метрикам после роста корпуса.
7. R-007 опирается на возраст из документа; если указан возраст на момент
   рассмотрения, а не на момент деяния, требуется ручная проверка
   (отмечено в объяснении правила).
