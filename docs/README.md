# Документация

Указатель по документам проекта. Начать стоит с того раздела, который
отвечает вашей задаче, — читать всё подряд не нужно.

## С чего начать

| Вы | Читайте по порядку |
|---|---|
| Разбираетесь, что это за система | [PRODUCT_VISION.md](PRODUCT_VISION.md) -> [ARCHITECTURE.md](ARCHITECTURE.md) -> [GLOSSARY.md](GLOSSARY.md) |
| Собираетесь править код | [../README.md](../README.md#разработка) -> [ARCHITECTURE.md](ARCHITECTURE.md) -> [DOMAIN_MODEL.md](DOMAIN_MODEL.md) |
| Проверяете юридическую часть | [LEGAL_SAFETY_PRINCIPLES.md](LEGAL_SAFETY_PRINCIPLES.md) -> [RULE_ENGINE.md](RULE_ENGINE.md) -> [DATA_SOURCES.md](DATA_SOURCES.md) |
| Подключаетесь к API | [API.md](API.md) |
| Разворачиваете систему | [../README.md](../README.md) -> [SECURITY.md](SECURITY.md) |
| Поднимаете модель на сервере Ubuntu | [DEPLOYMENT_VLLM.md](DEPLOYMENT_VLLM.md) |
| Оцениваете, что сделано | [CONCEPT.md](CONCEPT.md) -> [TZ.md](TZ.md) |
| Готовите документ для жюри конкурса | [CONCEPT.md](CONCEPT.md) |

## Требования и замысел

- [TZ.md](TZ.md) — техническое задание: пронумерованные требования, статус
  каждого, инварианты системы, очереди работ с указанием, что именно
  мешает закрыть каждую.
- [CONCEPT.md](CONCEPT.md) — концепция решения для отборочного этапа
  конкурса (п. 2.2 Положения): архитектура, данные, алгоритмы, правовая
  методология.
- [PRODUCT_VISION.md](PRODUCT_VISION.md) — для кого система, какую задачу
  решает и чего намеренно не делает.
- [GLOSSARY.md](GLOSSARY.md) — термины предметной области в том значении,
  в каком они употребляются в коде.

## Устройство системы

- [ARCHITECTURE.md](ARCHITECTURE.md) — слои, конвейер разбора, раскладка
  кода, границы между модулями, ключевые решения и отклонённые варианты.
- [DOMAIN_MODEL.md](DOMAIN_MODEL.md) — модели фактов, норм, оценок и
  отчёта; какие связи обязательны.

## Юридическая часть

- [LEGAL_SAFETY_PRINCIPLES.md](LEGAL_SAFETY_PRINCIPLES.md) — принципы
  безопасного обращения с правом: что система вправе утверждать, а что
  обязана оставить человеку.
- [RULE_ENGINE.md](RULE_ENGINE.md) — реестр детерминированных правил и
  порядок добавления нового.
- [LEGAL_RAG.md](LEGAL_RAG.md) — поиск по базе источников с обязательным
  цитированием.

- [DATA_SOURCES.md](DATA_SOURCES.md) — откуда берутся тексты норм и как
  корпус пополняется.

## Эксплуатация

- [API.md](API.md) — справочник HTTP API: пути, параметры, формы ответов
  и ошибок.
- [../README.md](../README.md) — профили развёртывания (в т.ч. Docker),
  переменные окружения, режимы авторизации.
- [DEPLOYMENT_VLLM.md](DEPLOYMENT_VLLM.md) — запуск языковой модели (vLLM)
  на сервере Ubuntu с видеокартой: установка, проверка, закрытый контур,
  разбор ошибок.
- [SECURITY.md](SECURITY.md) — модель угроз и состояние мер защиты.
- [PRIVACY.md](PRIVACY.md) — обращение с персональными данными,
  обезличивание, право на забвение.

## Качество

- [EVALUATION.md](EVALUATION.md) — метрики, датасеты и пороги, ниже
  которых сборка не принимается.

## Чего здесь нет

Рабочие заметки разработки — открытые вопросы, журнал изменений, листы сверки
для юриста, протоколы архитектурных решений — в репозитории не хранятся: они
нужны тому, кто ведёт разработку, и только запутали бы читателя, который
разбирается в системе. Итог по архитектурным решениям — в
[ARCHITECTURE.md](ARCHITECTURE.md), раздел «Ключевые решения».
