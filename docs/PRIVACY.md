# PRIVACY

Обращение с персональными данными (ПДн) и чувствительной информацией
судебных документов.

## Категории данных в системе

| Данные | Где обрабатываются | Куда передаются |
|---|---|---|
| Текст загруженного документа | память процесса, `data/store/documents/` | никуда (дефолт) |
| Извлечённые факты и отчёты | память процесса, `data/store/analyses/` | никуда (дефолт) |
| Хэши SHA-256, версии правил/промптов | `data/store/audit.jsonl` | никуда |
| Запросы поиска норм | память процесса | никуда |

## Режимы обработки

1. **Офлайн (по умолчанию).** LLM-провайдер — `mock`; внешние сетевые
   вызовы из конвейера анализа отсутствуют. Реальные судебные документы
   покидают машину только вместе с её носителем.
2. **Внешний LLM (`SO_LLM_PROVIDER=openai_compatible`).** Текст документа
   (первые 20 000 символов) отправляется на указанный
   `SO_OPENAI_BASE_URL`. Это осознанное решение оператора; для реальных
   дел допускается только:
   - в закрытом контуре (локальная/корпоративная модель за
     OpenAI-совместимым API), либо
   - после юридического разрешения передачи ПДн соответствующему провайдеру
     и обезличивания документов.

Ответственность за включение режима и выбор контура лежит на операторе;
система не переключает режимы сама.

## Хранение и удаление

- Всё локально: `SO_DATA_DIR` (по умолчанию `./data`).
- Удаление через API (право на забвение): `DELETE /api/v1/documents/{id}`
  удаляет документ и **все отчёты по нему** (каскад);
  `DELETE /api/v1/analyses/{id}` — отдельный отчёт. Обе операции фиксируются
  в аудит-журнале без текстов.
- Альтернатива: удалить JSON-файлы из `data/store/{documents,analyses}/`
  вручную; аудит-журнал содержит только хэши.
- Резервные копии каталога `data/` следует защищать как конфиденциальные.

## Резервные копии

Система хранит документы дословно и без шифрования на уровне приложения, поэтому
копия защищается так же, как сам каталог данных. Порядок для оператора:

1. **Что копировать.** Файловое хранилище: `data/store/` (документы, заключения,
   учётные записи, `audit.jsonl`). PostgreSQL (`SO_STORAGE_BACKEND=postgres`):
   дамп базы `second_opinion`; тома `pgdata` копировать файлами при работающей базе
   нельзя. Каталог `data/fixtures/` в репозитории и копируется вместе с ним.
2. **Шифровать до того, как копия покинет сервер.** Незашифрованный архив на
   внешнем диске или в общей папке раскрывает все загруженные приговоры. Например,
   с утилитой `age` (ключ шифрования хранится отдельно от копий):

   ```bash
   tar czf - -C data store | age -r "$SO_BACKUP_PUBLIC_KEY" > "so-store-$(date +%F).tar.gz.age"
   docker compose --profile postgres exec -T db pg_dump -U second_opinion -Fc second_opinion \
     | age -r "$SO_BACKUP_PUBLIC_KEY" > "so-db-$(date +%F).dump.age"
   ```

   Подойдёт и `gpg --encrypt`, и шифрование всего тома на уровне ОС (LUKS, FileVault);
   важно, чтобы расшифровать копию мог только ограниченный круг лиц.
3. **Проверять восстановление.** Копия, которую ни разу не разворачивали, копией не
   считается. Раз в квартал: расшифровать в пустой каталог или в отдельную базу,
   запустить сервис на этой копии и открыть любое заключение (раскрывается ли цитата).

   ```bash
   age -d -i "$SO_BACKUP_KEY_FILE" so-store-2026-10-07.tar.gz.age | tar xz -C /tmp/restore
   age -d -i "$SO_BACKUP_KEY_FILE" so-db-2026-10-07.dump.age | pg_restore -U second_opinion -d second_opinion_restore
   ```
4. **Сроки хранения и удаление.** Удаление документа через API копий не затрагивает:
   удалённый документ остаётся в старых копиях до их ротации. Срок хранения копий
   задаёт регламент суда, он же определяет, как исполнять просьбу об удалении;
   по умолчанию достаточно, чтобы срок ротации был не длиннее срока по регламенту.
5. **Журнал обращений к копиям** (кто и когда расшифровывал) ведёт оператор: система
   этого не видит.

Команды показывают порядок действий; на стенде проекта они не запускались, оператор
проверяет их на своей установке (в том числе наличие базы `second_opinion_restore`).

## Обезличивание (Д-06)

Обезличивание делается **на выходе, а не при загрузке**. Система хранит
дословный текст: без него нельзя выполнить инвариант «цитата дословно
находится в документе», на котором стоит доверие к отчёту. Поэтому
скрывается то, что покидает систему.

| Где | Как включается | Что происходит |
|---|---|---|
| Передача внешней модели | по умолчанию включено | текст маскируется с сохранением длины, поэтому оффсеты не сдвигаются и цитату видно по оригиналу |
| Выгрузка заключения | `?mask=true`, галочка в интерфейсе | фамилии в цитатах и изложении скрываются, в файл добавляется предупреждение |
| Подготовка образца для показа | `second-opinion anonymize файл.txt` | рядом кладётся обезличенная копия |

Что распознаётся: фамилия с инициалами и полное ФИО (включая падежные
формы), дата рождения, адрес, паспортные данные, СНИЛС, ИНН, телефон.

**Гарантии полноты нет и быть не может.** Пропущенное отчество или редкая
фамилия останутся в тексте. Это помощь человеку, а не замена его
решению: ответственность за проверку перед передачей остаётся на
операторе, и в интерфейсе это сказано прямо. Перечень сведений,
подлежащих исключению при публикации судебных актов, задан нормативно —
его подтверждает юрист, а не разработчик.

## Минимизация

- В аудит-журнал и логи тексты не пишутся (см. docs/SECURITY.md п. 4, 7).
- LLM-экстрактор ограничивает объём передаваемого текста
  (`MAX_DOCUMENT_CHARS = 20000`).

## Обязанности оператора

1. Загружать документы, обработка которых разрешена регламентом суда.
2. Не включать внешний LLM-контур без правового основания.
3. Ограничивать доступ к каталогу `data/` средствами ОС.
4. При демонстрациях использовать только синтетические фикстуры или
   обезличенные образцы (в репозитории все данные синтетические и явно
   помечены).
