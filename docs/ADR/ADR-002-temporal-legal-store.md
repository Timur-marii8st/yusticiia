# ADR-002: Хранилище норм с временны́ми редакциями

- Статус: принят (2026-08-25)

## Контекст

Право меняется. Редакция 2026 года не должна молча применяться к делу
2022 года. Нужен запрос нормы «на дату».

## Решение

Сущность `NormVersion` с `effective_from`/`effective_to` (null = действует),
текстом, санкциями, реквизитами источника, `retrieved_at` и SHA-256.
Единая точка доступа: `NormStore.get_norm(norm_id, applicable_at)` —
возвращает ровно одну редакцию или явную ошибку; пересечение интервалов
версий одной нормы запрещено и проверяется при загрузке.

## Альтернативы

- **Хранить только текущую редакцию:** неприемлемо — нарушает временну́ю
  корректность, один из главных юридических рисков конкурса.
- **База знаний с графом версий (RDF/Neo4j):** избыточно для десятков норм
  на этапе MVP.

## Последствия

+ проверяемая временна́я логика, контрольные суммы источников;
− каждую редакцию нужно вносить и датировать вручную (на MVP допустимо,
  фикстуры маркируются `verification_status: draft`).
