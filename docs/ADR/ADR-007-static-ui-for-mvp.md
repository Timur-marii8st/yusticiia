# ADR-007: MVP-интерфейс — статическая страница без сборщика

- Статус: принят (2026-08-25); путь миграции — отдельный фронтенд

## Контекст

Задание допускает «любой разумный современный стек». Первому срезу нужен
работающий экран анализа, а не фронтенд-инфраструктура; сборка
React/Next.js замедляет итерации и требует Node-инструментов в контуре,
где их может не быть.

## Решение

Один статический экран (`src/second_opinion/static/`): HTML + CSS + vanilla
JS без шага сборки; раздаётся тем же FastAPI-приложением, общается с
собственным REST API. Дизайн — спокойный, информационно-плотный,
прогрессивное раскрытие (карточка → обстоятельства с цитатами → проверки с
цепочками → практика → аналитика).

Миграция на React/Next.js возможна без изменения контрактов:
все данные уже отдаются JSON-эндпоинтами (`/api/...`).

## Альтернативы

- **Сразу Next.js:** дороже на старте, не нужен для первого среза. Отложено.
- **Серверный шаблонизатор (Jinja):** допустимо, но JS-раскрытие цепочек
  доказательств проще на клиенте; отклонено.

## Последствия

+ ноль инструментов сборки, мгновенные итерации;
− нет компонентной базы для крупных экранов (порог — ~5–7 экранов,
  дальше миграция).
